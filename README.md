# Telegram-бот для загрузки файлов на Яндекс Диск

Отправляешь боту файл — он спрашивает, на какой диск и в какую папку его положить, и загружает. Любой человек может подключить свой Яндекс Диск и стать его админом: выбрать корневую папку, задать название диска и добавить пользователей, которым разрешено туда загружать файлы.

## Возможности

- Загрузка документов, фото, видео, аудио, голосовых и видеосообщений на Яндекс Диск.
- Выбор папки кнопками: бот показывает подпапки корневой папки диска.
- Несколько дисков: каждый, кто подключил диск, становится админом своего диска со своим списком пользователей. Один человек может быть привязан к нескольким дискам, тогда бот сначала спрашивает, на какой диск грузить.
- Названия дисков (`/diskname`), по которым пользователи выбирают нужный диск.
- Подключение диска по коду входа через Яндекс или вручную по OAuth-токену.
- Токены хранятся в зашифрованном виде.
- Защита от злоупотреблений: бот работает только в личных чатах, есть лимит файлов в минуту на человека.
- Файл с таким именем на диске не перезаписывается: бот добавляет к имени `(1)`, `(2)` и т.д.

## Как это работает

После `/start` бот показывает две кнопки:

1. **Подключить диск.** Человек становится админом своего диска. Ему открываются все команды управления: токен, корневая папка, название диска, список пользователей.
2. **Загрузить файл.** Работает, если человека добавил какой-то админ. Если нет, бот отвечает: «Вас нет в списке пользователей. Обратитесь к админу.» и показывает ID человека, чтобы тот мог отправить его админу.

Обычному пользователю доступны только `/start`, `/help` и загрузка файлов.

## Требования

- Python 3.10 или новее.
- Токен бота от [@BotFather](https://t.me/BotFather).
- Аккаунт Яндекса (для подключения диска).
- Для входа по коду: приложение на [oauth.yandex.ru](https://oauth.yandex.ru) (необязательно, см. ниже).

## Установка

```bash
git clone https://github.com/biokarlson/uploader_naspb_bot.git
cd uploader_naspb_bot

python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env             # затем заполни .env
```

Запуск:

```bash
python bot.py
```

## Настройка `.env`

| Переменная | Обязательна | Описание |
|---|---|---|
| `BOT_TOKEN` | да | Токен бота от @BotFather |
| `ENCRYPTION_KEY` | да | Ключ шифрования токенов Яндекса в `data.json` |
| `YANDEX_CLIENT_ID` | нет | ClientID приложения Яндекса (для входа по коду) |
| `YANDEX_CLIENT_SECRET` | нет | Client secret приложения Яндекса |
| `RATE_LIMIT_PER_MIN` | нет | Сколько файлов в минуту может отправить один человек (по умолчанию 10) |

Ключ шифрования генерируется один раз:

```bash
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

> **Важно:** не меняй и не теряй `ENCRYPTION_KEY`. Без него сохранённые токены не прочитать, и всем админам придётся подключать диски заново. Если делаешь резервную копию `data.json`, сохраняй её вместе с ключом.

## Как подключаются диски

### Вариант 1. Вход по коду (удобно для людей)

Один раз создай приложение Яндекса:

1. Открой [oauth.yandex.ru](https://oauth.yandex.ru) и нажми «Создать приложение».
2. Платформа: **Веб-сервисы**. В поле Callback URI укажи `https://oauth.yandex.ru/verification_code`.
3. Права: **Яндекс.Диск REST API** → `cloud_api:disk.read` и `cloud_api:disk.write`. Права «app_folder» не нужны: они дают доступ только к отдельной папке приложения.
4. Скопируй `ClientID` и `Client secret` в `.env` (`YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`).

Дальше любой человек подключает диск сам: `/start` → «Подключить диск» → открывает ссылку, входит в свой аккаунт Яндекса, разрешает доступ, получает код и отправляет его боту.

### Вариант 2. Токен вручную

Если `YANDEX_CLIENT_ID` и `YANDEX_CLIENT_SECRET` не заданы, вход по коду отключён. Тогда админ получает OAuth-токен Яндекс Диска сам и отправляет его командой `/settoken ТОКЕН`. Бот сразу удаляет сообщение с токеном из чата.

Токены Яндекса действуют примерно год. Когда срок выйдет, админу достаточно снова пройти подключение диска.

## Команды

### Для всех

| Команда | Описание |
|---|---|
| `/start` | Главное меню: подключить диск или загрузить файл |
| `/help` | Справка |
| *(отправка файла)* | Выбор диска (если их несколько) и папки, затем загрузка |

### Для админа

| Команда | Описание |
|---|---|
| `/settings` | Название диска, статус подключения, корневая папка, число пользователей |
| `/code КОД` | Подтвердить вход через Яндекс (код можно просто отправить сообщением) |
| `/settoken ТОКЕН` | Задать OAuth-токен вручную |
| `/setroot` | Выбрать корневую папку кнопками |
| `/setroot /Путь/к/папке` | Задать корневую папку вручную |
| `/diskname [название]` | Показать или задать название диска (до 30 символов, уникальное среди всех дисков) |
| `/adduser ID` | Разрешить человеку загружать файлы на твой диск |
| `/removeuser ID` | Убрать человека из списка |
| `/users` | Список добавленных пользователей |
| `/logout` | Отключить диск: токен удаляется, список пользователей и настройки сохраняются |

Числовой ID человека можно узнать у бота [@userinfobot](https://t.me/userinfobot). Если человек написал боту без доступа, бот сам показывает ему его ID.

## Ограничения

- Обычный Bot API отдаёт боту файлы только до **20 МБ**. Для больших файлов нужен собственный сервер [Telegram Bot API](https://github.com/tdlib/telegram-bot-api).
- Бот работает только в личных чатах, в группах он не отвечает.
- В клавиатуре выбора папки показывается до 90 подпапок.
- Данные хранятся в `data.json` рядом с ботом, поэтому запускать нужно один экземпляр бота.

## Безопасность

- Токены Яндекса шифруются ключом `ENCRYPTION_KEY` и хранятся в `data.json` (права файла 600). Файлы `.env` и `data.json` в репозиторий не попадают благодаря `.gitignore`.
- Токен Яндекса даёт доступ ко всему Диску аккаунта. Относись к `.env` и `data.json` как к паролям: не публикуй их и не пересылай.
- Если `.env` когда-то попал в репозиторий или чат, отзови токены (бота: `/revoke` у @BotFather; Яндекса: в настройках аккаунта на id.yandex.ru) и выпусти новые.
- Админ видит названия папок на своём диске, и пользователи, которых он добавил, тоже видят их при выборе папки. Добавляй только тех, кому доверяешь.

## Запуск на сервере (systemd)

Пример сервиса `/etc/systemd/system/yadisk-bot.service`:

```ini
[Unit]
Description=Yandex Disk Telegram bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/uploader_naspb_bot
ExecStart=/opt/uploader_naspb_bot/.venv/bin/python bot.py
Restart=always
RestartSec=5
User=botuser

[Install]
WantedBy=multi-user.target
```

Включение и управление:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now yadisk-bot
sudo systemctl status yadisk-bot
journalctl -u yadisk-bot -f        # логи
```

Перед выбором сервера проверь, что с него доступны `api.telegram.org` и `cloud-api.yandex.net`.

## Частые проблемы

| Симптом | Что делать |
|---|---|
| При запуске: «не задан ENCRYPTION_KEY» | Сгенерируй ключ командой выше и впиши в `.env` |
| «Код не подошёл» | Код одноразовый и недолговечный: открой ссылку из `/start` → «Подключить диск» заново и отправь новый код. Проверь, что у приложения указан Callback URI `https://oauth.yandex.ru/verification_code` |
| «Токен недействителен» | Админу нужно снова пройти `/start` → «Подключить диск» |
| «Вас нет в списке пользователей» | Отправь админу диска свой ID, чтобы он выполнил `/adduser ID` |
| Файл больше 20 МБ не загружается | Ограничение Telegram, см. раздел «Ограничения» |
| Бот молчит в группе | Бот работает только в личных чатах |
| После смены `ENCRYPTION_KEY` диски «отвалились» | Верни прежний ключ или пусть админы подключат диски заново |
